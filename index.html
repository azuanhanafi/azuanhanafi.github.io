P/02 · Self-initiated · Rolling out

JIRA Change Management Architecture

JIRA Change Control Redesign - Turkish Aerospace Malaysia (TUSAS)

Change requests, configuration items, and SCCB reviews all ran in JIRA without one defined structure: items had no consistent ID, key fields could be left blank, and SCR/PR/ECM decisions lived in free-text meeting minutes with no system-enforced link to the ticket, routed and chased by hand. Designed a change management architecture that gives every change one controlled path from request through SCCB review to closure, built from three parts:

  1. Standard Item ID scheme - every configuration item and change request follows one traceable naming convention, so items can be traced across baselines and related changes linked.
  2. Mandatory field enforcement - change request issue types stop incomplete records at entry instead of at audit.
  3. SCCB workflow automation - a dedicated SCCB Review issue type, native digital Approvals for unanimous, timestamped sign-off, and three Automation Rules that move changes through review and approval with status updates and notifications.

Built a full traceability matrix mapping every governance rule to its Jira mechanism, and caught a design flaw before build where unanimous approval over an empty approver field would auto-pass with zero real sign-offs. Management approved the design; now leading the rollout with the SCCB and engineering teams, validating each part before it replaces the manual process.
